# #2 2×2 프로토콜 사전등록 — 생성기 × 피드백 분리 비교 (2026-10-24, 계획 §14.2 #2)

> 실행 전 평가기 동결. 배치 `linux/explore-2x2.sh`(커밋 후 실행, R12). 기존 600s×3 결과(H3·G4)는 탐색적 해석 유지 — 본 프로토콜의 결과가 그 해석을 대체하지 않고, ON 우위가 증명되지 않으면 **OFF 기저선을 유지**한다(계획 §14.2 원칙).

## 1. 4셀 정의 (동일 환경)

- **F축(생성기)**: `F` = 융합 풀(FlowFusion 프로그램을 시퀀스 스텝으로, `--fused-pool`), `H` = 과거 부류 수명주기 문법(기본 문법, 풀 없음).
- **피드백축**: `0` = `--feedback off`, `1` = `--feedback state`(H3에서 확립된 유일한 유효 ON 변형 — 구 'on'은 G4에서 열성 판정).
- 셀: **F0, F1, H0, H1** = {F,H} × {off,state}.
- 공통 환경(전 셀 동일 강제): PHP `8.4.27-asanext`(`binary_sha256` 일치 필수), SAPI=cli, 옵서버=gdb(기본값), opcache on, 예산 600초/런, 시드 {1,2,3}(셀당 3런, 총 12런), 융합 풀 = `fused-pool.py --count 200 --seed 11`로 **1회 생성해 F0·F1이 동일 파일 재사용**(프로그램 매칭).

## 2. 지표(전 항목 분모 명시)와 판정 규칙(동결)

- 1차: **time-to-first-valid-finding**(`time_to_first_valid_finding`, 미발견=600s 상수취급) — 셀 평균 및 시드별 방향.
- 2차: **distinct 서명 수**(`findings` 키 수), **unique feedback keys**(`unique_keys` 합계, G/R/A 부류별).
- 분모·건전성: `execs`(유효 실행), `wall_s`(600±60s), `harness_errors=0`, `aborted=false`, 문법 다양성(`grammar`). 모든 비율은 execs 기반으로 보고.
- **ON(OH) 우위 판정(각 생성기축별, 동결)**: state가 off를 이기려면 ① distinct 서명 수 평균 ≥ ② time-to-first 평균 단축 + 시드 ≥2/3 방향 일치 ③ `execs` 감소 ≤25%(다양성·처리량 붕괴 방지 — H3 v1의 열성 원인 재발 차단). **하나라도 미충족 시 OFF 기저선 유지를 판정으로 한다.**
- F0 vs H0(생성기축, OFF 동일조건)는 기술적 비교로만 보고(판정 규칙 없음).
- 반례 컨트롤(#76167=R08·#79760=R18·#10026=R23·#24361=R49·#16726=R35): 발견 서명은 기록 대조 분류 — **알려진 서명을 신규로 주장 금지**, 미지 서명은 D1 홀드(로컬 보관, ON 우위 근거로 사용 불가).
- hold-out: R23/R46/R51은 풀·튜닝·평가 어디에도 투입하지 않는다(기존 H3 0/3 판정 동결).

## 3. 무효화 조건(fail-closed)

- 어느 런이든 `harness_errors>0`·`aborted`·예산 이탈(>660s)·`binary_sha256` 불일치 → 해당 런 무효, 동일 시드 재실행(재실행 사실 기록). 2회 무효 시 셀 전체 미측정으로 보고.
- 배치 종료 코드 비영 시 결과 보고 금지(원인 기록 후 재실행).

## 4. 결과 보고 형식(동결)

셀×지표 표(평균±시드별), ON 판정 충족 여부 체크리스트(①②③), F0/H0 기술 비교, 컨트롤 분류 결과, 무효 런 기록. findings §12.8에 기록하고 계획 §14.3 순위 5를 종결한다.
