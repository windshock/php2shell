## 가장 먼저 해결할 불일치

### P0: 반복 실행과 ASAN 증거 연결

- 최신 결과: `var/linux-evidence/evidence/poc-20261021T131039-502-8.4.4-tracked/result.json`.
- 이 JSON은 `iterations=5`, `reproduced=5`를 기록하지만 5개 회차 모두 `asan.503`과 같은 첫 프레임을 참조한다.
- 같은 디렉터리에는 `asan.503`, `asan.505`, `asan.507`, `asan.510`, `asan.512`가 실제 존재한다. 따라서 오류 관측 자체를 부정할 수는 없지만, 회차별 독립 증거 연결은 현재 JSON으로 입증되지 않는다.
- `linux/poc-bgserialize.py`의 `read_asan()` 및 회차별 수집 범위를 검토한다. 이전 회차 로그를 다음 회차 결과로 재사용하는지, 현재 회차 PID·시간·출력 디렉터리와 일치하는지 확인한다. 원인을 확정하기 전에는 가설로 표시한다.
- 이전 결과 `poc-20261021T130943-468-8.4.4-tracked/result.json`은 `reproduced=0`인데 같은 디렉터리에 ASAN 파일 5개가 있다. 결과 보고서 §4.5는 그 파일명(`asan.469`~`asan.484`)을 5/5의 근거로 인용한다. 로그 본문·회차 출력과 연결해 집계 및 인용 오류 여부를 확인한다.
- 완료 기준: 각 회차의 실제 프로세스·독립 ASAN 로그·결과 판정이 대응하고, 성공/실패 집계와 문서 인용이 일치한다. 과거 원본 증적은 덮어쓰지 않는다.

### P0: 문서 시각 불일치

- 점검 당시 현지 시각은 2026-10-21 22:18 KST이다.
- 계획 §9.6과 결과 §4.5에 `23:10 추가`라는 미래 시각이 있다.
- 해당 파일의 수정 시각은 각각 약 22:10:57 및 22:11:03 KST이고, 최신 커밋 시각은 22:11:35 KST이다.

- 공식 패치의 예정 시각도 기존 문서의 주장이다. 예정 시각 경과만으로 공개 완료를 간주하지 않는다.

### P1: 환경 상태와 분석 판정의 범위 구분

- `environment-status.json`은 `scope: environment readiness, not a vulnerability verdict`, `cve_verdict: not_run`으로 기록되어 있다.
- 후속 분석과 날짜가 다른 환경 스냅샷일 수 있으므로 최신 분석 판정과 다르다는 이유만으로 오류로 단정하지 않는다.
- 관측된 메모리 오류, 반복 재현율, 운영 구성 영향, CVE 일치 여부를 각각 분리해서 보고한다.

## 이어서 할 일

1. 위 P0 두 항목을 기존 증적의 읽기 전용 검토로 먼저 확인하고, 담당자가 검토한 결과를 이 문서와 결과 보고서에 반영한다.

4. 공식 1차 출처에서 보안 공지·패치·수정 버전을 확인한 뒤, 동일 입력·SAPI·INI 조건의 회귀 비교 계획을 갱신한다.

기존 계획의 범위는 소유한 격리 랩의 방어적 검증이다. 외부·운영 대상 시험, 무기화된 코드 실행 체인, 공개 공격 코드 실행은 기존 계획의 비목표로 명시되어 있다. 이 인수인계는 실행 실패를 우회하거나 원래 범위를 확대하는 요청이 아니다.
